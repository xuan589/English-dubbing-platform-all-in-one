# 英语配音一站式工具 — 架构方案

## 技术选型

| 层 | 选型 | 理由 |
|---|------|------|
| 桌面壳 | Electron | 双击启动、跨平台、自带 Chromium |
| 前端 | React + TypeScript + Vite | 组件化开发、热更新、生态成熟 |
| 后端 | Python FastAPI | 轻量、支持 WebSocket 推送进度、和 AI 模型同一语言 |
| 人声分离 | demucs (HTDemucs) | Phase 1 已验证通过，PyPI 安装，模型自动下载 |
| 语音转写 | ffmpeg 内置 Whisper (whisper.cpp) | Phase 1 已验证通过，比 Python 版快 3 倍，无需额外装包 |
| 音视频处理 | ffmpeg | 已安装，全功能 |
| 数据存储 | 文件系统 + JSON | 一个作品一个文件夹，全流程非破坏性 |

### 已安装/已验证的依赖

- Python 3.13.9 ✓
- Node.js v24.14.0 / npm 11.9.0 ✓
- ffmpeg 8.1.2 ✓
- PyTorch 2.12.0（已装）✓
- demucs 4.1.0（已装）✓
- Whisper 模型：base 已验证，最终版提供 base/small/medium 三档可选

## 数据组织

每个配音作品 = 一个文件夹，结构如下：

```
projects/我的作品/
├── project.json           # 所有元数据（句子、录音记录、设置）
├── source/
│   └── clip.mp4           # 截取的原始片段
├── separated/
│   ├── vocals.wav         # demucs 分离的人声
│   └── accompaniment.wav  # demucs 分离的伴奏
├── transcript/
│   └── sentences.json     # 转写后的句子列表 + 时间轴
├── recordings/
│   └── sentence_01/
│       ├── take_01.wav    # 第 1 次录音（不可覆盖）
│       ├── take_02.wav    # 第 2 次录音
│       └── selected.txt   # 当前选中的 take 编号
├── intro/                 # 用户选择的片头文件
├── outro/                 # 用户选择的片尾文件
├── export/                # 最终导出
│   └── final.mp4
└── logs/                  # 诊断日志
```

**关键原则：**
- 所有中间产物以文件形式落盘，永不覆盖旧录音
- `project.json` 记录当前状态，关软件重开自动恢复
- 打开项目 = 打开这个文件夹，所有进度都在

## 系统架构

```
┌─────────────────────────────────────────────┐
│                  Electron                    │
│  ┌───────────────────────────────────────┐  │
│  │          React 前端 (Vite)             │  │
│  │  ┌─────┐ ┌──────┐ ┌────┐ ┌────────┐  │  │
│  │  │导入 │ │分离  │ │录音│ │导出    │  │  │
│  │  └─────┘ └──────┘ └────┘ └────────┘  │  │
│  │         ↕ REST API + WebSocket         │  │
│  └───────────────────────────────────────┘  │
│  ┌───────────────────────────────────────┐  │
│  │         Python FastAPI 后端            │  │
│  │  ┌──────────┐ ┌──────────┐           │  │
│  │  │ demucs   │ │  ffmpeg  │           │  │
│  │  │ 人声分离  │ │ whisper  │           │  │
│  │  └──────────┘ └──────────┘           │  │
│  └───────────────────────────────────────┘  │
└─────────────────────────────────────────────┘
```

- **启动流程：** Electron 启动 → 自动拉起 Python 后端 → 打开前端页面
- **通信：** 前端调 REST API 发起任务，后端通过 WebSocket 推送进度
- **长任务处理：** 分离、转写、导出都在后台线程跑，WebSocket 实时推送百分比

## 核心流程

### 1. 导入与截取
1. 用户选择视频文件 → 前端播放器预览
2. 拖动起止时间点 → 精确截取（重编码，保证帧精确）
3. 把截取片段存到 `source/clip.mp4`

### 2. 人声分离
1. 点"分离"按钮 → 后端调 demucs
2. WebSocket 推送进度（百分比 + 预估剩余时间）
3. 输出 `vocals.wav` + `accompaniment.wav`

### 3. 语音转写
1. 分离完成后自动触发 → 后端调 ffmpeg whisper
2. 产出 `sentences.json`：`[{id, start, end, text}, ...]`
3. 前端展示句子列表，每条显示序号、时间、文本

### 4. 逐句录音
1. 选中某句 → 显示原始音频波形为参考
2. 点录音 → Web Audio API 录音 → 保存为 `take_N.wav`
3. 不满意点重录 → 自动编号 `take_N+1.wav`，旧文件保留
4. A/B 对比：列表里选两个 take，来回切换播放
5. 界面显示「原句 3.2 秒 / 你录了 4.1 秒」供参考

### 5. 预览
- **单句试听：** 只放录音
- **单句叠伴奏：** 录音 + 对应时段的伴奏
- **全片预览：** 从头到尾播一遍（替换后的音轨 + 字幕）

### 6. 合成导出
1. 混音：伴奏轨 + 所有已确认录音，对齐时间轴
2. 拼接：片头 → 正片 → 片尾
3. 烧字幕：经典影视风（黑底白字细轮廓）
4. 编码：H.264 + AAC，CRF 18
5. 输出 `export/final.mp4`

## 界面布局

**核心设计原则：配音时必须看到视频画面。** 点击任意句子 → 视频跳到对应时刻 → 用户盯着画面录 → 录音控件在视频正下方，余光可见。

```
┌──────────────────────────────────────────────────────────┐
│  🐱 作品名称                     [片头] [片尾] [导出]     │  ← 顶栏
├────────────────────────────────────┬─────────────────────┤
│                                    │  句子列表            │
│         视频播放器                  │  ┌───────────────┐  │
│         (大尺寸、主要视线区)        │  │ #1  0:00→0:03 │  │
│                                    │  │ "Hello..."  ✓ │  │
│         ┌──────────────────┐       │  │ #2  0:03→0:06 │  │
│         │     🐱 吉祥物     │       │  │ "How are..."  │  │  ← 右侧栏
│         │   (右下角小窗)    │       │  │ #3  0:06→0:08 │  │    可滚动
│         └──────────────────┘       │  │ "I'm fine"  ✓ │  │
│                                    │  │ #4  0:08→0:11 │  │
├────────────────────────────────────┤  │ ...           │  │
│  当前句：#2  "How are you?"        │  └───────────────┘  │
│  ┌────────────────────────────────┐│                     │
│  │        参考波形 + 录音波形      ││                     │
│  │   （原句音频波形作背景参考）     ││                     │
│  └────────────────────────────────┘│                     │
│  ● 录音  ▶ 试听  ↺ 重录  🔁 循环  │                     │
│  原句 3.2s / 你录了 4.1s           │                     │
│  [take_01 ✓] [take_02] [A/B 对比]  │                     │
├────────────────────────────────────┴─────────────────────┤
│  🐱 状态栏：就绪  |  已录 5/12 句  |  🔇 静音音效        │  ← 底栏
└──────────────────────────────────────────────────────────┘
```

**为什么这样布局：**
- 视频占主视野（左上到中间），是配音时盯着的核心区域
- 录音控件紧挨视频下方，看画面的同时余光扫到波形和按钮
- 句子列表在右侧，点击即可跳句——右手鼠标操作、视线在左侧视频
- 吉祥物小窗叠加在视频右下角，不占独立空间，录音时才"竖耳朵"有存在感
- 底栏显示整体进度：已录几句、还剩几句

**配色方案：** 暖色系（奶油黄 + 浅橘），配合圆角小猫元素。工作区背景深灰，减少视觉疲劳。

## 吉祥物状态

| 状态 | 表现 |
|------|------|
| 待机 | 小猫趴着打瞌睡，偶尔耳朵动一下 |
| 处理中 | 小猫推着一个进度条小球往前走 |
| 录音中 | 小猫竖起耳朵，眼睛睁大看着你 |
| 录得好 | 小猫点头，冒出小心心 |
| 导出完成 | 小猫跳起来撒花 |
| 出错 | 小猫翻倒，冒汗 |
| 空状态 | 小猫举牌"还没导入片段哦" |

## 错误处理策略

- 所有错误提示翻译成大白话（"片源打不开"而不是"FileNotFoundError"）
- 常见问题单独处理：片源格式不支持、麦克风没权限、磁盘空间不足、模型未下载完成
- 界面右下角始终有「复制诊断信息」按钮，一键复制日志
- 所有耗时操作不可中途关闭的，弹窗提示"正在处理，请勿关闭"

## 启动脚本设计

`start.bat` 需要自动完成以下检查（用户只需双击）：

1. 检查 Python → 没有则提示安装
2. 检查 Node.js → 没有则提示安装
3. 检查 ffmpeg → 没有则自动安装（winget）
4. 检查依赖包 → 没有则自动 pip install / npm install
5. 检查 Whisper 模型文件 → 没有则自动从国内镜像下载
6. 启动 Python 后端 → 启动 Electron 前端
7. 浏览器自动打开或 Electron 窗口显示

首次启动可能需要 5-10 分钟装依赖，后续启动应在 5 秒内完成。
